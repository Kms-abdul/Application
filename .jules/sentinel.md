## 2025-02-18 - Missing Role-Based Authorization in Admin Endpoint
**Vulnerability:** The `/api/users/add` endpoint used `@token_required` for authentication but completely lacked a role check, allowing any authenticated user to create new accounts, including those with 'Admin' privileges. This is a critical privilege escalation and broken access control vulnerability.
**Learning:** The `@token_required` decorator only ensures the user is authenticated, it does not enforce authorization. Admin-only endpoints must explicitly verify the user's role (e.g., `if current_user.role != 'Admin':`) after authentication. The lack of global blueprint authorization means each route is individually responsible for its own authorization checks.
**Prevention:** Always verify both authentication *and* authorization (role-based access control) on sensitive endpoints. Do not assume authentication implies authorization. Create a custom decorator (e.g., `@admin_required`) to standardize and enforce this check across administrative routes, reducing the risk of omission.
