## 2025-03-02 - [Fix SQL Injection Risk via String Concatenation in Report Card Attendance Query]
**Vulnerability:** A vulnerability to SQL injection exists in `erp-backend/routes/report_card_routes.py` due to string concatenation using Python f-strings in a SQL query. Instead of using parameterized queries, raw values obtained from the database are formatted directly into the query `conditions.append(f"(MONTH(date) = {m['month']} AND YEAR(date) = {m['year']})")`.
**Learning:** Even when data originates from the database (e.g., `m['month']`, `m['year']`), string concatenation for building queries can introduce second-order SQL injection risks. The data from the database is still considered untrusted context. Furthermore, dynamically building SQL WHERE clauses should use `%s` parameters that are passed into `cursor.execute()` alongside the query string.
**Prevention:** Avoid any f-string interpolation or string concatenation when dynamically building SQL queries. Instead, build a list of parameters alongside the query string and pass the parameters as a tuple to `cursor.execute(query, tuple(params))`.
