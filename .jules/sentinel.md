## 2025-05-18 - Prevent Second-Order SQL Injection in Dynamic Condition Building
**Vulnerability:** A second-order SQL injection vulnerability existed in `erp-backend/routes/report_card_routes.py` where string interpolation (`f"(MONTH(date) = {m['month']} AND YEAR(date) = {m['year']})"`) was used to build SQL query conditions dynamically using values retrieved from the database instead of using parameterized queries.
**Learning:** Even if data originates from the database (e.g., `mapped_months`), it must not be trusted for direct SQL string interpolation. Using f-strings or `.format()` for building queries creates a risk of second-order SQL injection if the stored data was ever compromised or manipulated.
**Prevention:** Always construct SQL query strings with `%s` placeholders and dynamically append/extend the corresponding values to a parameter list (`att_params`). Pass the finalized list as a tuple to `cursor.execute(query, tuple(params))` to safely handle arbitrary numbers of parameters and completely eliminate SQL injection vectors.
