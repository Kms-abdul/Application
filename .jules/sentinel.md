## 2025-04-23 - Hardcoded Development Secrets Can Leak into Production
**Vulnerability:** A hardcoded secret (`"dev-only-secret-key-change-before-production"`) was used as a fallback for the Flask `SECRET_KEY` when the environment variable was missing in non-production environments.
**Learning:** Even though the explicit check for production throws an error if `SECRET_KEY` is not provided (or is too short), having a hardcoded key as a fallback in development environments is an anti-pattern. If a non-production instance is accidentally exposed, or if the environment variable `ENV` is incorrectly set to "development" while running in a production-like context, the system is completely compromised because the signing key is known to attackers.
**Prevention:** Always generate a completely random, secure fallback key dynamically (e.g., using `os.urandom(32).hex()`) in non-production environments if an explicit key isn't provided. This ensures that every run of the server gets a unique key, preventing key reuse and known-key attacks even in development setups.
