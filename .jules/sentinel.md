## 2024-06-03 - SQL Injection in Report Card Attendance Query
**Vulnerability:** A raw SQL query constructed in `erp-backend/routes/report_card_routes.py` dynamically embeds raw values retrieved from the database (`mapped_months`) using Python f-strings, exposing it to potential second-order SQL injection. The issue lies around line 488: `conditions.append(f"(MONTH(date) = {m['month']} AND YEAR(date) = {m['year']})")`.
**Learning:** Even when building a query with values retrieved directly from a database (e.g. mapping table), if those values aren't properly parameterized using `%s`, it creates a potential injection point should a malicious or unexpectedly formatted string find its way into the mapping table.
**Prevention:** Always use placeholder parameterization (`%s` in `mysql.connector` or `sqlite3`) for ALL dynamically injected values in raw SQL queries, regardless of their source (even other database tables). Extend the `params` list dynamically to match the number of placeholders generated.
