## 2025-02-26 - Second-Order SQL Injection in Dynamic Query Construction
**Vulnerability:** A second-order SQL injection vulnerability existed in `erp-backend/routes/report_card_routes.py` where conditions for an attendance query were dynamically built using f-strings with data retrieved from the database (`mapped_months`).
**Learning:** Even if data originates from the database, it must not be interpolated directly into SQL queries using f-strings or `.format()`. If the initial database records were ever compromised or maliciously crafted, interpolating them into a subsequent query could lead to second-order SQL injection.
**Prevention:** Always use the database connector's parameterization feature (e.g., `%s` for `mysql.connector`). When dynamically constructing variable numbers of conditions, build the query string with `%s` placeholders and dynamically `.extend()` or `.append()` the values to a parameters list, executing it as `cursor.execute(query, tuple(params))`.
