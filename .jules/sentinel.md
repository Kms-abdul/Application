## 2024-07-20 - Second-Order SQL Injection via f-strings
**Vulnerability:** Found a second-order SQL injection vulnerability where data retrieved from the database (in this case `mapped_months`) was directly interpolated using f-strings into a new SQL query: `f"(MONTH(date) = {m['month']} AND YEAR(date) = {m['year']})"`.
**Learning:** Even if data originates from the database itself (e.g., from a prior SELECT query), using f-strings or `.format()` to build SQL queries is inherently risky and violates safe coding practices. This is a classic source of second-order SQL injection vulnerabilities if the stored data is ever manipulated or originally came from untrusted input without proper sanitization.
**Prevention:** Always use parameterized queries (e.g., `%s` with `mysql.connector`) for all dynamic values, regardless of whether the source is direct user input or data fetched from the database. Build the query string with placeholders and dynamically append the corresponding values to the parameter list tuple passed to `cursor.execute()`.
