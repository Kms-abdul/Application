## 2024-05-18 - Broken Access Control on User Creation
**Vulnerability:** The `/api/users/add` endpoint in `erp-backend/routes/auth_routes.py` had the `@token_required` decorator to check if the caller was authenticated, but it lacked a role-based authorization check. This allowed any authenticated user to create new accounts, including "Admin" accounts, leading to a Privilege Escalation vulnerability.
**Learning:** In this backend architecture, the `@token_required` decorator *only* verifies authentication. Administrative endpoints (e.g., creating users or modifying roles) must also include explicit role-based authorization checks (like `if current_user.role != 'Admin':`) to prevent broken access control. The application does not enforce global authentication or authorization on Flask blueprints.
**Prevention:** Ensure that all endpoints intended for specific roles explicitly check the `current_user.role` after the `@token_required` decorator, especially those creating users, changing roles, or migrating data.
